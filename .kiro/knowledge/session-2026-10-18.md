## KEY DECISION THIS SESSION: NetworkX instead of Neo4j
- User rejected Neo4j as "too big and bulky" for a trial/learning project (~100 nodes).
- Chose **NetworkX** (in-process, pure-Python, file-persisted JSON — no server, no Docker, no port, no password). Right-sized for ~31 nodes/48 edges.
- Kept a **backend-agnostic interface** (GraphStore) so a server-backed store (Neo4j) could be swapped later WITHOUT touching extraction/retrieval. The dormant neo4j_* config keys remain for that future.
- Alternatives discussed & rejected: Neo4j (too heavy), Kùzu (embedded but Cypher — offered if user wanted Cypher practice; user didn't), SQLite CTEs (awkward traversal), RDFLib (overkill). User did NOT want Cypher.
